# Inline editor review

1. **High — `optimizer.js:161-173,469-485`: editor initialization overwrites persisted form state before it is restored.** `createUmaInlineEditor` calls `set`, which emits `onUmaChange` synchronously; `persist()` replaces the in-memory `saved` object and localStorage with the default controls, empty inherited list and default race. The later startup reads that overwritten object. Reloading after choosing a custom race or tuning settings silently loses them. **Fix:** suppress persistence until startup restoration is complete, or preserve the original saved state independently and initialize the editor after restoring the other controls. Add a reload test with non-default race, settings and inherited skills.

2. **Medium — `uma-editor.js:615-626`, `optimizer.js:327-354`: an in-flight import can change the disabled editor during a run.** If a user selects a large file and starts Optimize before `file.text()` resolves, disabling the enclosing fieldset does not cancel the asynchronous import. Its continuation replaces the draft and persists it while the run is active, so the displayed input no longer describes the frozen runner being optimized. **Fix:** invalidate or cancel pending imports when the editor is disabled, or prevent Optimize until the import settles; add a delayed-file test.

3. **Medium — `optimizer.js:237-245`: the full build card does not show the unique skill.** `umaChipBody` renders the portrait and stats/aptitudes, and `skillRows` lists only `entry.build`; the unique is present in `runner(entry.build).skills` but is never displayed. A user cannot verify the unique or its level on a result, despite the revised output requiring each full uma with its skills. **Fix:** render the runner's unique ID and level alongside the bought skills (and its activation rate if available), while retaining SP costs only for purchases.

4. **Low — `uma-editor.js:709-712`, `optimizer.js:173,80-82`: the editor initially receives no course until the pool index has loaded.** A user can select a character while that fetch is pending or fails; `setOutfit` then skips the course-specific surface and distance defaults and the displayed aptitudes stay at the blank draft defaults. **Fix:** initialize the inline editor with `races.currentCourse()` immediately, and update it on every race change independently of pool-index availability.

No modal-editor regression was identified in the shared-code diff by inspection. The fieldset disables ordinary inline controls during runs, and no removed picker references remain on the optimizer page. `node --test tests/` passed all 66 tests; the suite does not exercise the inline or modal UI in a browser.

## Fix check

All four reported issues are addressed by the inspected paths: restoration suppresses persistence and preserves choices while selects are empty; an import completing while the fieldset is disabled is rejected; result cards render the unique and level; and the editor receives the current course at creation and on race changes. Snapshot ordering now handles the tested mixed formats and is used for both meeting and custom selection. `node --test tests/` passed all 67 tests. The inline UI fixes were verified by inspection, not browser interaction.
